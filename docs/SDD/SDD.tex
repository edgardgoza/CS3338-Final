\section{Introduction}

\subsection{Purpose}
This Software Design Document describes the design of PD-Intranet, a role-based internal SharePoint resource center for the Santa Barbara County Public Defender's Office. It explains how the system is structured, how components interact, and how the user interface is organized.

\subsection{Intended Audience}
This document is intended for developers, QA testers, project managers, instructors, and future maintainers who need to understand the technical design of the system.

\subsection{Overview}
PD-Intranet is built on SharePoint Framework (SPFx) using React and TypeScript. It uses Microsoft identity services to authenticate users and assign roles, then shows each user only the content and tools relevant to their role. The system replaces manual permission management with an automated, role-driven approach.

\subsection{Site Breakdown}
\begin{itemize}
  \item \textbf{Authentication Layer:} Users sign in with Microsoft credentials. Azure Entra ID or Active Directory groups determine each user's role.
  \item \textbf{SPFx Frontend:} Reusable React web parts handle each feature (announcements, directories, workload views, procedure checklists). Navigation and content are filtered by role.
  \item \textbf{Data Layer:} Data is stored in SharePoint lists and document libraries. PnP.js and Microsoft Graph API retrieve and filter data.
  \item \textbf{Analytics Layer:} Power BI dashboards are embedded or linked for approved roles.
  \item \textbf{Admin Layer:} IT and admin users manage SharePoint lists, role assignments, and content libraries.
\end{itemize}

\section{User Interface}

\subsection{How to Use}
Users access PD-Intranet through a SharePoint URL provided by their office. After signing in with their Microsoft account, they are taken to their role-specific home dashboard. Navigation links only show pages the user has permission to view. No manual setup is required from the user.

\subsection{Pages and Tools}
\begin{itemize}
  \item \textbf{Home Dashboard:} Landing page showing role-specific announcements and quick links.
  \item \textbf{Role-Based Resource Page:} Manuals, forms, and office documents filtered by role.
  \item \textbf{Office Hoteling Page:} Allows staff to reserve desks or shared workspaces.
  \item \textbf{Attorney Workload Page:} Displays and allows searching of case distribution data.
  \item \textbf{Expert Witness Directory:} Searchable list of expert contacts with availability.
  \item \textbf{CDD Resource Guide:} Resources specific to Capital Defense Division staff.
  \item \textbf{Urgency Portal:} Analytics dashboard for supervisors and IT roles.
  \item \textbf{Admin / Maintenance Page:} Tools for IT staff to manage lists and permissions.
\end{itemize}

\subsection{Database Explanation}
Data is stored in SharePoint Lists and Document Libraries. Each list corresponds to a feature (e.g., a hoteling reservation list, a staff directory list). PnP.js queries these lists and returns only records the user's role is permitted to see. No external database is used.

\section{Security Design}
\begin{itemize}
  \item Authentication is handled through Microsoft identity services.
  \item Authorization is role-based using Azure Entra ID or Active Directory groups.
  \item Restricted pages require the correct role assignment.
  \item Secrets and credentials must not be committed to GitHub.
\end{itemize}

\section{Deployment Design}
The system is deployed through SharePoint App Catalog as an SPFx package. A Docker setup may be used locally for planning and placeholder services during development.
