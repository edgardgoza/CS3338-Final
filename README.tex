\section{Introduction}
PD-Intranet is an internal website we built for the Santa Barbara County Public Defender's Office. The idea is that each employee only sees the stuff that is relevant to their job instead of having access to everything at once.

\section{Why This Software Matters}
Before PD-Intranet, all employees had access to every office resource regardless of their role. This caused:
\begin{itemize}
    \item Information overload for staff who did not need certain resources
    \item Security and compliance risks from unrestricted access to sensitive content
    \item Manual permission management that was slow and error-prone
    \item Delays when employees changed roles or departments
\end{itemize}
PD-Intranet solves this by giving each employee a personalized view of only the tools and resources relevant to their job, with permissions managed automatically through Azure Active Directory.

\section{Goals}
\begin{itemize}
    \item Reduce manual permission management
    \item Improve resource accessibility for all staff
    \item Enhance productivity with personalized dashboards
    \item Ensure secure, role-based access to sensitive information
\end{itemize}

\section{Objectives}
\begin{itemize}
    \item Implement role-based access control for 9 user roles
    \item Automate permission sync using Azure Active Directory
    \item Build modular SharePoint web parts for each department
    \item Deploy an office hoteling and attorney workload dashboard
\end{itemize}

\section{How to Access}
\begin{enumerate}
    \item Clone the repository from GitHub
    \item Install dependencies: \texttt{npm install}
    \item Build the SPFx solution: \texttt{gulp bundle --ship \&\& gulp package-solution --ship}
    \item Deploy the \texttt{.sppkg} file to the SharePoint App Catalog
    \item Access the platform via your SharePoint site
\end{enumerate}
